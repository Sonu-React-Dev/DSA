#1. The Universal 15-Step MAANG Interview Blueprint

Top interviewers at Google, Meta, and Apple do not evaluate you merely on whether your code compiles. They evaluate your problem deconstruction, communication, and systematic bottleneck identification. Follow this structured timeline:

Phase Target Minutes Step # Action Item & What to Say Aloud
Phase 1: Problem Clarification 00 – 05 min Step 1 Clarify Constraints: Ask: "What is the range of N? Can values be negative? Are duplicates possible? Is the array sorted?"
Step 2 Confirm Input/Output: State: "Given input [2, 7, 11, 15] and target 9, we return indices [0, 1]. In case of no answer, should we return empty array or throw error?"
Step 3 Identify Edge Cases: Check: Empty input, single element, all identical values, large numbers exceeding 32-bit limits.
Phase 2: Brute Force & Bottleneck 05 – 12 min Step 4 Formulate Brute Force: Never stay silent! Say: "The most straightforward brute force is checking every pair using nested loops."
Step 5 Analyze Brute Force Complexity: State: "This takes O(N^2) time and O(1) space. With N = 10^5, N^2 = 10^10 operations which will Time Out (TLE)."
Step 6 Identify the Bottleneck: Ask yourself aloud: "What work is being repeated? For each element, we repeatedly search the rest of the array. How can we make this search O(1)?"
Phase 3: Pattern & Optimal Strategy 12 – 18 min Step 7 Select Pattern: Say: "Since we need instantaneous O(1) lookups for the complement (target - current), a Hash Map is optimal."
Step 8 State the Invariant: "Invariant: At any step i, the Map contains all elements from 0 to i - 1 with their indices."
Step 9 Get Interviewer Buy-in: Ask: "This brings time down to O(N) with O(N) space. Does this approach sound good to proceed with coding?"
Phase 4: Clean Implementation 18 – 32 min Step 10 Write Idiomatic JavaScript: Use const, let, descriptive variable names, native Map or Set. Avoid clever one-liners.
Step 11 Speak While Coding: Verbalize your logic: "Here I am checking if map has complement; if yes, return indices; otherwise save current element."
Step 12 Defensive Coding: Guard against null, empty arrays, or off-by-one pointer errors early in the function body.
Phase 5: Verification & Follow-ups 32 – 45 min Step 13 Step-by-Step Dry Run: Trace code with a concrete example table. Never press "Run" without manual dry-run verification!
Step 14 Confirm Final Complexity: Explicitly state: "Time Complexity is O(N) linear pass; Auxiliary Space is O(N) for the Hash Map."
Step 15 Discuss Follow-ups & Scale: Offer: "If space is constrained to O(1), we could sort first and use Two Pointers in O(N log N) time."

#2. How Should I Think About This? (The 10-Question Discovery Engine)

Whenever you read an unfamiliar problem statement, ask these 10 questions in order to automatically trigger the correct solution path:

# Question to Ask Yourself Signal / Deductive Reasoning Action / Data Structure Trigger
Q1 What is the size of N? $N \le 20 \implies$ Exponential; $N \le 10^5 \implies O(N \log N)$ or $O(N)$ Filters out impossible algorithms immediately.
Q2 Is the data sorted or can it be sorted? Sorted array or monotonic property Trigger: Binary Search or Two Pointers.
Q3 Is the problem asking for a contiguous subarray/substring? Keywords: "continuous", "longest valid substring", "fixed window K" Trigger: Sliding Window or Prefix Sum.
Q4 Do I need to repeatedly find the minimum or maximum element? Dynamic stream with highest/lowest priority Trigger: Min-Heap / Max-Heap or Monotonic Queue.
Q5 Does the next element depend on the previous greater/smaller element? Keywords: "next warmer day", "stock span", "histogram area" Trigger: Monotonic Stack ($O(N)$ one pass).
Q6 Are there discrete choices at each step with ability to undo? Keywords: "all permutations", "generate all combinations", "solve board" Trigger: Backtracking / State-Tree DFS.
Q7 Are identical subproblems being computed repeatedly? Overlapping subproblems + optimal substructure Trigger: Dynamic Programming (Memoization / Tabulation).
Q8 Can local choices guarantee global optimality without reconsidering? Interval scheduling, greedy choice property Trigger: Greedy Algorithm with Sorting.
Q9 Does the problem model relationships, prerequisites, or shortest paths? Entities connected by edges, dependency order Trigger: BFS (unweighted), Dijkstra (weighted), Topo Sort (DAG).
Q10 Can state be represented in bits or hardware operations? Pairs canceling out, subset masks for $N \le 20$ Trigger: Bit Manipulation (XOR, Kernighan, Bitmasks).

#4. JavaScript V8 DSA Complexity & Memory Traps

JavaScript has engine-specific behaviors in Google's V8 engine that can ruin an otherwise optimal algorithmic design:

Operation / Pattern Naive Mental Model V8 Actual Reality Interview Defense Rule
arr.sort() Sorts numbers in ascending order Converts numbers to strings! [10, 2].sort() returns [10, 2] because "10" < "2"! Always use: arr.sort((a, b) => a - b).
queue.shift() Removes from front in $O(1)$ $O(N)$ linear time! Re-indexes every single remaining element in memory! Use pointer head index or a Doubly Linked List / Circular Array for queues.
str += char inside loop Appends character $O(N)$ per append! JS strings are immutable; each concatenation creates a brand new heap allocation ($O(N^2)$ total). Use arr.push(char) inside loop and arr.join('') at the end ($O(N)$ amortized).
Math.max(...arr) Finds maximum in array Throws RangeError on large arrays ($N > 65,536$)! Arguments are pushed onto the limited V8 execution call stack. Use a simple for-loop: let max = -Infinity; for (const x of arr) if (x > max) max = x;
Plain Object {} as Map Hash table with $O(1)$ lookup Only supports string/symbol keys; has prototype pollution risk; slower hash transitions in V8. Always prefer native new Map() for arbitrary keys and frequent insertions/deletions.
Recursion depth Unlimited stack frames V8 call stack maximum limit is typically $pprox 10,000$ calls before Maximum call stack size exceeded. Convert deep recursion ($N = 10^5$) to iterative loops with explicit array stack.
Bitwise operators (&, |, ^) Works on standard JS 64-bit float Truncates to 32-bit signed integer! Values $> 2^{31}-1$ wrap around to negative numbers! Use BigInt or >>> 0 for unsigned operations; verify numbers fit within 32 bits.

#7. Pattern vs Pattern Head-to-Head Showdowns

Confusion between similar patterns is the #1 reason candidates fail coding interviews. Study these head-to-head comparisons:

Comparison Pattern A Pattern B How to Decide Which One to Pick
Two Pointers vs Sliding Window Two Pointers: Converging from both ends (L=0, R=N-1) or reading two separate arrays. Sliding Window: Both pointers move rightward (L and R) bounding a contiguous range. If the array is sorted and you need a pair $\implies$ Two Pointers. If you need a contiguous subarray satisfying a condition $\implies$ Sliding Window.
Sliding Window vs Prefix Sum Sliding Window: Expands and shrinks dynamically in $O(N)$ time and $O(1)$ space. Prefix Sum: Cumulative sum array with Hash Map lookup in $O(N)$ time and $O(N)$ space. CRITICAL RULE: If the array contains negative numbers, Sliding Window FAILS because expanding the window can decrease the sum! You MUST use Prefix Sum + Hash Map.
BFS vs DFS BFS: Explores level-by-level using a FIFO Queue. DFS: Explores branch deeply using recursion stack. If looking for shortest path in unweighted graph or level-order views $\implies$ BFS. If looking for all paths, topological sort, or subtree calculations $\implies$ DFS.
Greedy vs Dynamic Programming Greedy: Makes irrevocable local choice; never backtracks or stores overlapping states. DP: Explores all valid combinations via recurrence and caches subproblem results. Greedy requires the Greedy-Choice Property. If picking a local best can lock you out of a globally superior answer (e.g. Coin Change with coins $[1, 3, 4]$ and target 6) $\implies$ DP is mandatory.
Top-Down (Memo) vs Bottom-Up (Tab) Top-Down: Recursive function + Cache Map/Array. Intuitive state transitions. Bottom-Up: Iterative loops + DP Table. Zero recursion call stack overhead. Start with Top-Down during brainstorming to visualize base cases. Convert to Bottom-Up in the interview to guarantee $O(1)$ stack space and enable 1D rolling array optimization.
Fenwick Tree vs Segment Tree Fenwick Tree: 10 lines of code, $N+1$ array memory, ultra-fast L1 cache constant factor. Segment Tree: $4N$ array memory, supports arbitrary associative operations (Min, Max, GCD). If the problem only requires invertible operations like Range Sum or Range XOR with point updates $\implies$ Fenwick Tree. If range queries involve Range Minimum/Maximum or Range Updates $\implies$ Segment Tree with Lazy Propagation.

#5.11 Stack using JavaScript Array

📊 ASCII Trace 
Stack = LIFO (Last In, First Out)

push 3  → [3]
push 5  → [3, 5]
push 1  → [3, 5, 1]
pop     → removes 1, stack = [3, 5]
peek    → 5 (top, not removed)
⚡ JavaScript 
// Stack using Array — built-in push/pop are O(1)!
class Stack {
  constructor() {
    this.items = [];
  }
  
  push(val) {
    this.items.push(val);      // O(1)
  }
  
  pop() {
    if (this.isEmpty()) return null;
    return this.items.pop();   // O(1)
  }
  
  peek() {
    if (this.isEmpty()) return null;
    return this.items[this.items.length - 1];  // O(1)
  }
  
  isEmpty() {
    return this.items.length === 0;  // O(1)
  }
  
  size() {
    return this.items.length;  // O(1)
  }
}

// Usage
const stack = new Stack();
stack.push(10);
stack.push(20);
stack.push(30);
stack.peek();   // 30
stack.pop();    // 30
stack.peek();   // 20
stack.size();   // 2

📊 ASCII Trace 
Queue = FIFO (First In, First Out)

enqueue 3 → [3]
enqueue 5 → [3, 5]

// ✅ Efficient Queue using head pointer
class Queue {
  constructor() {
    this.items = {};
    this.head = 0;
    this.tail = 0;
  }
  
  enqueue(val) {
    this.items[this.tail] = val;  // O(1)
    this.tail++;
  }
  
  dequeue() {
    if (this.isEmpty()) return null;
    const val = this.items[this.head];  // O(1)
    delete this.items[this.head];
    this.head++;
    return val;
  }
  
  front() {
    return this.items[this.head];  // O(1)
  }
  
  isEmpty() {
    return this.head === this.tail;
  }
  
  size() {
    return this.tail - this.head;
  }
}

#15. Interview Questions

#Conceptual Questions (with answers):

Q1: What is the difference between Map and Object in JavaScript?

A: Map allows any key type (even objects/arrays), maintains insertion order, has .size, and performs better for frequent add/delete. Objects only support string/symbol keys. For DSA, prefer Map for frequency counting and lookup tables.

Q2: Why is arr.shift() O(N) but arr.pop() O(1)?

A: pop() removes from the END — no elements need to move. shift() removes from the START — all remaining elements must shift their indices by 1, making it O(N).

Q3: What is the difference between slice and splice?

A: slice(start, end) returns a new array and does NOT modify original. splice(start, deleteCount, ...items) modifies the original array in-place and returns removed elements.

Q4: Why should we avoid arr.sort() without a comparator?

A: JavaScript's default sort converts elements to strings and sorts lexicographically. [10, 2].sort() gives [10, 2] instead of [2, 10] because '1' < '2' in string comparison.

Q5: What is the difference between reference types and value types?

A: Primitive types (number, string, boolean, null, undefined) are passed by value — a copy is made. Objects and arrays are passed by reference — both variables point to the same memory location. Modifying through one reference affects all.

#1. What is it?

Time Complexity ka matlab code run hone mein kitna time (seconds) lega yeh calculate karna NAHI hai. Time Complexity yeh measure karta hai ki jab input size ($N$) grow karta hai, toh operations kitni tezi se badhte hain.

  • Simple shabdon mein: "Agar input 10 se 1,000,000 ho jaye, toh mera code kitna slow ho jayega?"
  • Real-world hardware (Mac M2, slow laptop, server) par second ka count alag hoga, isliye computer science mein hum Big-O Notation use karte hain jo machine-independent hota hai.

#2. Why do we need it?

  • Interviews mein rejection ka #1 reason: Code chal toh raha hai, lekin interview constraints $N = 10^5$ hain aur aapne $O(N^2)$ solution likh diya. Result: TLE (Time Limit Exceeded).
  • Predictability: Code likhne se pehle aap constraints dekhkar bata sakte ho ki kaunsa algorithm chalega aur kaunsa fail hoga.
  • Standard benchmark rule:
    • Modern online judges (LeetCode, Codeforces) 1 second mein lagbhag $10^8$ operations execute karte hain.
    • Agar $N = 10^5$ hai aur aapka code $O(N^2)$ hai: $(10^5)^2 = 10^{10}$ operations $\rightarrow$ 100 seconds! TLE confirm.
    • Agar $O(N \log N)$ hai: $10^5 \times 17 \approx 1.7 \times 10^6$ operations $\rightarrow$ < 0.05 seconds! Accept.

#3. Real-world analogy

Socho aapko ek book mein se ek specific word dhundna hai:

  • $O(1)$ [Constant]: Book ka page number pehle se pata hai. Seedha open kiya — 1 second.
  • $O(N)$ [Linear]: Pehle page se aakhri page tak line-by-line read kar rahe ho. Agar book 100 pages ki hai toh 100 steps, 1000 pages ki hai toh 1000 steps.
  • $O(\log N)$ [Logarithmic]: Book sorted hai (dictionary). Beech mein open kiya, dekha word aage hai ya peeche, half part eliminate kar diya. 1,000,000 words mein sirf ~20 jumps lagenge!
  • $O(N^2)$ [Quadratic]: Har page ke har word ko book ke baki sabhi words ke saath compare karna. 1000 pages ki book ke liye $1,000,000$ operations!

#4. Important Terminology

Term Symbol Meaning Interview Relevance
Big-O $O(N)$ Upper Bound (Worst Case) — Code isse bura perform kabhi nahi karega. 99% interviews mein yahi pucha jata hai.
Big-Omega $\Omega(N)$ Lower Bound (Best Case) — Sabse ideal condition mein kitna minimum time lagega. Rarely asked, conceptual clarity ke liye.
Big-Theta $\Theta(N)$ Tight Bound (Average Case) — Jab upper aur lower bound same hon. Academic discussions.
Asymptotic Analysis — Input $N \rightarrow \infty$ (infinity) hone par algorithm ka behavior study karna. Foundation of algorithm comparison.
Amortized Time — Ek occasional expensive operation ko regular cheap operations mein divide karke average nikalna (e.g., dynamic array resizing). Very high frequency in JS array interviews!

#5. Rules of Big-O Calculation

#Rule 1: Drop Constants

$O(2N) \rightarrow O(N)$
$O(500) \rightarrow O(1)$
$O(3N^2 + 5N + 100) \rightarrow O(N^2)$
Kyun? Kyunki jab $N = 10^9$ hota hai, toh constant $2$ ya $500$ koi significant difference nahi banata.

#Rule 2: Drop Non-Dominant Terms

Agar equation hai: $O(N^2 + N + \log N)$
Hamesha sabse bada term rakho: $O(N^2)$. Kyunki jab $N = 10,000$, toh $N^2 = 100,000,000$, jabki $N$ sirf $10,000$ hai (negligible).

#Hierarchy of Complexities (Fastest to Slowest):

$$O(1) < O(\log N) < O(\sqrt{N}) < O(N) < O(N \log N) < O(N^2) < O(N^3) < O(2^N) < O(N!)$$

#7. Dry Run & Complexity Tracing Example

Aaiye ek common interview trap function ko trace karte hain:

⚡ JavaScript 
function trickyFunction(n) {
  let count = 0;
  for (let i = 1; i <= n; i++) {
    for (let j = 1; j <= n; j += i) {
      count++;
    }
  }
  return count;
}

#Manual Step Trace:

  • Jab $i = 1$: $j$ increments by 1 $\rightarrow$ runs $n/1$ times ($n$ steps).
  • Jab $i = 2$: $j$ increments by 2 $\rightarrow$ runs $n/2$ steps.
  • Jab $i = 3$: $j$ increments by 3 $\rightarrow$ runs $n/3$ steps.
  • ...
  • Jab $i = n$: runs $n/n = 1$ step.

$$\text{Total Steps} = n \times \left( \frac{1}{1} + \frac{1}{2} + \frac{1}{3} + \dots + \frac{1}{n} \right)$$ Yeh mathematics ki famous Harmonic Series hai: $$\sum_{k=1}^n \frac{1}{k} \approx \ln(n) + \gamma$$ $$\text{Total Time Complexity} = O(n \ln n) = O(N \log N)$$ (Interviewers love this question! Normal student $O(N^2)$ bolte hain, par actual answer $O(N \log N)$ hai).

  • ❌ Hidden $O(N)$ inside loop:

    ⚡ JavaScript

#1. What is it?

Space Complexity ka matlab hai ki aapka algorithm execute hone ke dauran total kitni extra memory (RAM) allocate karta hai relative to input size ($N$).

  • Total Space: Input data space + Extra auxiliary space.
  • Auxiliary Space: Sirf woh additional memory jo algorithm apne logic ko complete karne ke liye temporary variables, arrays, sets, ya call stack ke roop mein mangta hai.
  • Interview Standard: Jab interviewer puche "What is the space complexity?", 99% time unka matlab Auxiliary Space se hota hai.

#2. Why do we need it?

  • Memory Limits on LeetCode / Servers: Mobile devices ya cloud lambda functions mein limited memory (128MB–256MB) hoti hai.
  • Memory Leaks & Out of Memory (OOM): Agar aap $10^7$ integers ka array JS mein banate ho, toh V8 engine mein ~80MB–160MB memory lag sakti hai.
  • Call Stack Overflow: Recursive calls deep hone par JS engine throws RangeError: Maximum call stack size exceeded (typically ~10,000 stack frames).

#3. Real-world analogy

Socho aap kitchen mein ek recipe cook kar rahe ho:

  • Input Space: Raw vegetables, spices, oil jo recipe ke liye zaroori hain.
  • Auxiliary Space: Cutting board, bowls, pans, aur utensils jo aapne chopping aur mixing ke liye use kiye.

#5. Space Complexity Categories & Examples

#Category 1: $O(1)$ Auxiliary Space (In-Place / Constant)

⚡ JavaScript 
// Array reverse in-place: O(1) Auxiliary Space
function reverseArray(arr) {
  let left = 0;
  let right = arr.length - 1;
  while (left < right) {
    let temp = arr[left];
    arr[left] = arr[right];
    arr[right] = temp;
    left++;
    right--;
  }
  return arr; // Mutated original array, no new data structures!
}

    seen.add(num);
  }
  return duplicates;
}

  if (arr[mid] === target) return mid;
  if (arr[mid] > target) return binarySearchRec(arr, target, low, mid - 1);

#4. GCD & LCM (Euclidean Algorithm)

#Mathematical Insight:

$$\gcd(a, b) = \gcd(b, a \pmod b)$$ Base Case: Jab $b == 0$, toh answer $a$ hai.

#Implementation in JavaScript ($O(\log(\min(a, b)))$):

⚡ JavaScript 
// 1. Recursive Euclidean GCD
function gcd(a, b) {
  return b === 0 ? a : gcd(b, a % b);
}

// 2. Iterative Euclidean GCD
function gcdIterative(a, b) {
  while (b !== 0) {
    let temp = b;
    b = a % b;
    a = temp;
  }
  return a;
}

// 3. LCM (Least Common Multiple) formula:
// a * b = gcd(a, b) * lcm(a, b)
function lcm(a, b) {
  if (a === 0 || b === 0) return 0;
  return Math.abs(a * b) / gcd(a, b);
}

console.log(gcd(48, 18)); // 6
console.log(lcm(12, 18)); // 36

  if (n <= 2) return 0;
  
  // Initialize boolean array with true
  const isPrimeArr = new Uint8Array(n);
  isPrimeArr.fill(1);
  isPrimeArr[0] = 0;
  isPrimeArr[1] = 0;

  for (let p = 2; p * p < n; p++) {
    if (isPrimeArr[p] === 1) {
      // Mark multiples of p starting from p * p
      for (let i = p * p; i < n; i += p) {
        isPrimeArr[i] = 0;
      }
    }
  }

  let count = 0;
  for (let i = 2; i < n; i++) {
    if (isPrimeArr[i] === 1) count++;
  }
  return count;
}

#6. Fast Exponentiation (Binary Power) — $O(\log N)$

Simple multiplication $x^n$ karne par $O(N)$ lagta hai ($x = 2, n = 10^9 \rightarrow$ TLE). Binary Exponentiation isse $O(\log N)$ mein solve karta hai: $$x^n = (x^2)^{n/2} \quad \text{(if } n \text{ is even)}$$ $$x^n = x \times x^{n-1} \quad \text{(if } n \text{ is odd)}$$

#Implementation (LeetCode #50: Pow(x, n)):

⚡ JavaScript 
function myPow(x, n) {
  if (n === 0) return 1.0;
  let power = n;
  if (power < 0) {
    x = 1 / x;
    power = -power;
  }

  let result = 1;
  let currentBase = x;

  while (power > 0) {
    // If power is odd, multiply result
    if (power % 2 === 1) {
      result *= currentBase;
    }
    currentBase *= currentBase; // Square the base
    power = Math.floor(power / 2); // Halve the power
  }

  return result;
}

console.log(myPow(2.0, 10)); // 1024

#Pattern B: Reverse an Integer with 32-bit Overflow Check (LeetCode #7)

⚡ JavaScript 
function reverseInteger(x) {
  const INT_MAX = 2147483647;      // 2^31 - 1
  const INT_MIN = -2147483648;     // -2^31
  
  let rev = 0;
  let n = Math.abs(x);
  
  while (n > 0) {
    let pop = n % 10;
    n = Math.floor(n / 10);
    
    // Check overflow before multiplying
    if (rev > Math.floor(INT_MAX / 10)) return 0;
    rev = rev * 10 + pop;
  }
  
  rev = x < 0 ? -rev : rev;
  return (rev < INT_MIN || rev > INT_MAX) ? 0 : rev;
}

#1. What is it?

Recursion ka matlab hai: Ek function jo khud ko hi call karta hai ek chhote sub-problem ke liye, jab tak ki woh sabse basic problem (Base Case) tak na pahunch jaye.

  • The Recursion Equation: $$\text{Badi Problem} = \text{Chhoti Sub-problem ka Answer} + \text{Current Step ka Kaam}$$
  • Har Recursive Function ke 2 Zaroori Parts hote hain:
    1. Base Case: Kab rukna hai! (Stop condition). Agar yeh nahi doge toh infinite loop $\rightarrow$ Call Stack Overflow crash!
    2. Recursive Case: Function ka apne aap ko call karna with a smaller/reduced input ($n - 1$ ya $n / 2$).

#2. Why do we need it?

  • Trees & Graphs are 100% Recursive: Trees (Binary Tree, BST, Trie) aur Graphs (DFS) naturally recursive data structures hain. Recursion ke bina inka code likhna bohot messy aur mushkil hota hai.
  • Backtracking & Dynamic Programming Base: DP aur Backtracking (N-Queens, Sudoku Solver, Permutations) ka base recursion hi hai. Agar recursion weak hai, toh DP samajh aana namumkin hai.

#3. Real-world analogy: Russian Nesting Dolls (Matryoshka)

  1. Aapne badi doll kholi $\rightarrow$ uske andar ek choti doll nikli (Recursive call).
  2. Choti doll kholi $\rightarrow$ aur choti doll nikli.
  3. Aakhri doll kholi jo solid wood ki hai aur khul nahi sakti $\rightarrow$ Yeh Base Case hai!
  4. Ab aap reverse order mein sabko wapas band karte huye bahar aate ho $\rightarrow$ Stack Unwinding / Returning values!

#Problem 4: Generate All Subsets (Power Set) Intro

⚡ JavaScript 
function getSubsets(nums) {
  const result = [];

  function backtrack(index, current) {
    // Base Case: Every decision path reaches an end
    if (index === nums.length) {
      result.push([...current]); // Push copy of current subset
      return;
    }

    // Choice 1: Include nums[index]
    current.push(nums[index]);
    backtrack(index + 1, current);

    // Choice 2: Exclude nums[index] (Backtrack step)
    current.pop();
    backtrack(index + 1, current);
  }

  backtrack(0, []);
  return result;
}

How to Think About Array Problems in an Interview

When handed an array problem, do not immediately jump to coding nested loops:

  1. Is the array sorted? If yes, immediately consider Binary Search or Two Pointers. If no, ask if sorting $O(N \log N)$ is acceptable under constraints.
  2. Are we looking for a contiguous subarray? Think Kadane's (for max sum), Sliding Window (positive numbers / fixed window), or Prefix Sum + Hash Map (contains negative numbers).

⚡ Kadane's Algorithm: Brute Force ➔ Better ➔ Optimal Evolution

Approach Core Idea Time Complexity Space Complexity Bottleneck / Why Too Slow
1. Brute Force Generate all $O(N^2)$ subarrays and compute their sum with a 3rd loop. $O(N^3)$ $O(1)$ Re-adds every element repeatedly from scratch. Times out for $N > 500$.
2. Better (Prefix Sum / Running Sum) Fix starting index $i$, expand end index $j$, maintain cumulative sum. $O(N^2)$ $O(1)$ Still considers $O(N^2)$ pairs even when earlier subarray prefix was heavily negative.

    // If currentSum is negative, start fresh from nums[i]
    currentSum = Math.max(nums[i], currentSum + nums[i]);
    maxSum = Math.max(maxSum, currentSum);
  }

  return maxSum;
}

The Two Pointers Mathematical Invariant Proof

Why are we mathematically guaranteed not to miss the optimal answer when we increment left or decrement right?

Container With Most Water (#11) Proof:
Area = $\min(height[L], height[R]) \times (R - L)$. "The brute force for 3Sum takes O(N^3) by checking all triplets. We can optimize this to O(N^2) time and O(1) extra space by first sorting the array. For each index i, we search for pairs that sum to -nums[i] using two converging pointers, left and right. Because the array is sorted, if the sum is too small we increment left, and if it's too large we decrement right. To handle duplicate triplets without extra memory, we simply advance our pointers past any identical consecutive elements. This gives an optimal O(N^2) runtime." 
function threeSum(nums) {
  nums.sort((a, b) => a - b);
  const result = [];

  for (let i = 0; i < nums.length - 2; i++) {
    // Skip duplicate i
    if (i > 0 && nums[i] === nums[i - 1]) continue;
    if (nums[i] > 0) break; // Sorted array, impossible to sum to 0

    let left = i + 1;
    let right = nums.length - 1;

    while (left < right) {
      const sum = nums[i] + nums[left] + nums[right];
      if (sum === 0) {
        result.push([nums[i], nums[left], nums[right]]);
        while (left < right && nums[left] === nums[left + 1]) left++;
        while (left < right && nums[right] === nums[right - 1]) right--;
        left++;
        right--;
      } else if (sum < 0) {
        left++;
      } else {
        right--;
      }
    }
  }

  return result;
}

function lengthOfLongestSubstring(s) {

  let maxLen = 0;
  let left = 0;

  for (let right = 0; right < s.length; right++) {
    const char = s[right];
    if (lastSeen.has(char) && lastSeen.get(char) >= left) {
      // Jump left pointer past the previous occurrence
      left = lastSeen.get(char) + 1;
    }
    lastSeen.set(char, right);
    maxLen = Math.max(maxLen, right - left + 1);
  }

  return maxLen;
}

function minWindow(s, t) {

  const needMap = new Map();
  for (const c of t) needMap.set(c, (needMap.get(c) || 0) + 1);

  let required = needMap.size;
  let formed = 0;
  const windowCounts = new Map();

  let left = 0, right = 0;
  let minLen = Infinity;
  let startIdx = 0;

  while (right < s.length) {
    const char = s[right];
    windowCounts.set(char, (windowCounts.get(char) || 0) + 1);

    if (needMap.has(char) && windowCounts.get(char) === needMap.get(char)) {
      formed++;
    }

    // Shrink window from left as long as it satisfies condition

      if (right - left + 1 < minLen) {
        minLen = right - left + 1;
        startIdx = left;

      windowCounts.set(leftChar, windowCounts.get(leftChar) - 1);
      if (needMap.has(leftChar) && windowCounts.get(leftChar) < needMap.get(leftChar)) {
        formed--;
      }
      left++;
    }
    right++;
  }

  return minLen === Infinity ? "" : s.substring(startIdx, startIdx + minLen);
}

⚠️ The 3 Classic Binary Search Bug Traps & Solutions

  • Trap 1 (Integer Overflow): mid = Math.floor((low + high) / 2) can overflow in languages like C++/Java if $low + high > 2^{31}-1$. Defense: Always use low + Math.floor((high - low) / 2).
  • Trap 2 (Infinite Loop on 2 Elements): When low = 0, high = 1, mid evaluates to 0. If your logic sets low = mid, low never advances, causing an infinite freeze. Defense: Either strictly do low = mid + 1 / high = mid - 1, or use Math.ceil when assigning to low.
  • Trap 3 (Loop Condition Mismatch): Using low < high when you need to inspect the final single element at low === high. Defense: Use while (low <= high) for exact value search; use while (low < high) for boundary convergence search.
function binarySearch(nums, target) {
  let low = 0;
  let high = nums.length - 1;

  while (low <= high) {
    // Avoid (low + high) overflow in large integers
    const mid = low + Math.floor((high - low) / 2);

    if (nums[mid] === target) {
      return mid; // Target found
    } else if (nums[mid] < target) {
      low = mid + 1; // Discard left half
    } else {
      high = mid - 1; // Discard right half
    }
  }

  return -1; // Not found
}

      high = mid - 1;

    }
  }

}

function combinationSum(candidates, target) {
  const result = [];

  function backtrack(startIndex, current, remainingTarget) {
    if (remainingTarget === 0) {
      result.push([...current]);
      return;
    }

      current.push(candidates[i]);

  backtrack(0, [], target);

function partition(s) {
  const result = [];

  function isPalindrome(str, left, right) {
    while (left < right) {
      if (str[left++] !== str[right--]) return false;
    }
    return true;
  }

  function backtrack(startIndex, current) {
    if (startIndex === s.length) {
      result.push([...current]);
      return;

    for (let end = startIndex; end < s.length; end++) {
      if (isPalindrome(s, startIndex, end)) {

        backtrack(end + 1, current);
        current.pop();
      }
    }
  }

  backtrack(0, []);
  return result;
}

function exist(board, word) {
  const rows = board.length;
  const cols = board[0].length;

  function dfs(r, c, index) {
    if (index === word.length) return true;
    if (r < 0 || c < 0 || r >= rows || c >= cols || board[r][c] !== word[index]) {
      return false;
    }

    // Mark cell as visited in-place
    const temp = board[r][c];
    board[r][c] = '#';

    // Explore 4 directions: Up, Down, Left, Right
    const found = dfs(r + 1, c, index + 1) ||
                  dfs(r - 1, c, index + 1) ||
                  dfs(r, c + 1, index + 1) ||
                  dfs(r, c - 1, index + 1);

    // Unchoose: restore original character
    board[r][c] = temp;
    return found;
  }

  for (let r = 0; r < rows; r++) {
    for (let c = 0; c < cols; c++) {
      if (board[r][c] === word[0] && dfs(r, c, 0)) {
        return true;
      }
    }
  }

  return false;
}

function solveNQueens(n) {
  const result = [];
  const cols = new Set();
  const posDiag = new Set(); // (r + c)
  const negDiag = new Set(); // (r - c)

  // Initialize empty n x n board
  const board = Array.from({ length: n }, () => new Array(n).fill('.'));

  function backtrack(r) {
    if (r === n) {
      result.push(board.map(row => row.join('')));
      return;
    }

    for (let c = 0; c < n; c++) {
      if (cols.has(c) || posDiag.has(r + c) || negDiag.has(r - c)) {
        continue; // Pruned! Queen can attack this spot.
      }

      // 1. Choose
      cols.add(c);
      posDiag.add(r + c);
      negDiag.add(r - c);
      board[r][c] = 'Q';

      // 2. Explore next row
      backtrack(r + 1);

      // 3. Unchoose
      cols.delete(c);
      posDiag.delete(r + c);
      negDiag.delete(r - c);
      board[r][c] = '.';
    }
  }

  backtrack(0);
  return result;
}

function solveSudoku(board) {

    for (let i = 0; i < 9; i++) {
      if (board[r][i] === char) return false; // Check row
      if (board[i][c] === char) return false; // Check col
      // Check 3x3 subgrid box

      if (board[boxR][boxC] === char) return false;
    }
    return true;

    for (let r = 0; r < 9; r++) {
      for (let c = 0; c < 9; c++) {
        if (board[r][c] === '.') {

          return false; // No number 1-9 worked, trigger backtrack

      }
    }
    return true; // All cells filled correctly
  }

class MinHeap {
  constructor() {
    this.heap = [];
  }

  size() { return this.heap.length; }
  peek() { return this.heap.length === 0 ? null : this.heap[0]; }

  push(val) {
    this.heap.push(val);
    this._siftUp(this.heap.length - 1);
  }

  pop() {
    if (this.heap.length === 0) return null;
    if (this.heap.length === 1) return this.heap.pop();

    const min = this.heap[0];
    this.heap[0] = this.heap.pop();
    this._siftDown(0);
    return min;
  }

  _siftUp(index) {
    let curr = index;
    while (curr > 0) {
      const parent = Math.floor((curr - 1) / 2);
      if (this.heap[curr] < this.heap[parent]) {
        [this.heap[curr], this.heap[parent]] = [this.heap[parent], this.heap[curr]];
        curr = parent;
      } else {
        break;
      }
    }
  }

  _siftDown(index) {
    let curr = index;
    const len = this.heap.length;

    while (2 * curr + 1 < len) {
      let smallest = curr;
      const left = 2 * curr + 1;
      const right = 2 * curr + 2;

      if (left < len && this.heap[left] < this.heap[smallest]) {
        smallest = left;
      }
      if (right < len && this.heap[right] < this.heap[smallest]) {
        smallest = right;
      }

      if (smallest !== curr) {
        [this.heap[curr], this.heap[smallest]] = [this.heap[smallest], this.heap[curr]];
        curr = smallest;
      } else {
        break;
      }
    }
  }
}

    let curr = this.root;
    for (const char of word) {
      if (!curr.children[char]) {
        curr.children[char] = new TrieNode();
      }
      curr = curr.children[char];

    curr.isEndOfWord = true;

function numIslands(grid) {
  if (!grid || grid.length === 0) return 0;
  const rows = grid.length;
  const cols = grid[0].length;
  let count = 0;

  function dfs(r, c) {
    if (r < 0 || c < 0 || r >= rows || c >= cols || grid[r][c] === '0') {
      return;
    }

    grid[r][c] = '0'; // Sink island in-place (marks as visited)

    dfs(r + 1, c);
    dfs(r - 1, c);
    dfs(r, c + 1);
    dfs(r, c - 1);
  }

  for (let r = 0; r < rows; r++) {
    for (let c = 0; c < cols; c++) {
      if (grid[r][c] === '1') {
        count++;
        dfs(r, c);
      }
    }
  }

  return count;
}

function findOrder(numCourses, prerequisites) {
  const inDegree = new Array(numCourses).fill(0);
  const adj = Array.from({ length: numCourses }, () => []);

  // Build graph & in-degrees
  for (const [course, pre] of prerequisites) {
    adj[pre].push(course);
    inDegree[course]++;
  }

  // Queue holds all courses with 0 prerequisites
  const queue = [];
  for (let i = 0; i < numCourses; i++) {
    if (inDegree[i] === 0) queue.push(i);
  }

  const order = [];

  while (queue.length > 0) {
    const curr = queue.shift();
    order.push(curr);

    for (const nextCourse of adj[curr]) {
      inDegree[nextCourse]--;
      if (inDegree[nextCourse] === 0) {
        queue.push(nextCourse);
      }
    }
  }

  // If order length equals numCourses, no cycle exists!
  return order.length === numCourses ? order : [];
}

  for (const [u, v, w] of times) {
    adj[u].push([v, w]);
  }

function bellmanFord(edges, numVertices, source) {
  const dist = new Array(numVertices).fill(Infinity);
  dist[source] = 0;

  // Relax all edges V - 1 times
  for (let i = 1; i < numVertices; i++) {
    for (const [u, v, weight] of edges) {
      if (dist[u] !== Infinity && dist[u] + weight < dist[v]) {
        dist[v] = dist[u] + weight;
      }
    }
  }

  // Check for negative weight cycles
  for (const [u, v, weight] of edges) {
    if (dist[u] !== Infinity && dist[u] + weight < dist[v]) {
      return null; // Negative cycle detected!
    }
  }

  return dist;
}

#1. What is it?

$$d[i][j] = \min(d[i][j], d[i][k] + d[k][j])$$

⚡ JavaScript 
function floydWarshall(matrix, n) {
  const dist = matrix.map(row => [...row]);

  // Intermediate node k
  for (let k = 0; k < n; k++) {
    for (let i = 0; i < n; i++) {
      for (let j = 0; j < n; j++) {
        if (dist[i][k] !== Infinity && dist[k][j] !== Infinity) {
          dist[i][j] = Math.min(dist[i][j], dist[i][k] + dist[k][j]);
        }
      }
    }
  }

  return dist;
}

#1. Production-Grade Union-Find Class in JavaScript

⚡ JavaScript 
class UnionFind {
  constructor(size) {
    this.parent = Array.from({ length: size }, (_, i) => i);
    this.rank = new Array(size).fill(0);
    this.componentsCount = size;
  }

  // Path Compression: O(alpha(N)) ≈ O(1)
  find(x) {
    if (this.parent[x] !== x) {
      this.parent[x] = this.find(this.parent[x]);
    }
    return this.parent[x];
  }

  // Union by Rank: O(alpha(N)) ≈ O(1)
  union(x, y) {
    const rootX = this.find(x);
    const rootY = this.find(y);

    if (rootX === rootY) return false; // Already connected! (Cycle detected)

    if (this.rank[rootX] < this.rank[rootY]) {
      this.parent[rootX] = rootY;
    } else if (this.rank[rootX] > this.rank[rootY]) {
      this.parent[rootY] = rootX;
    } else {
      this.parent[rootY] = rootX;
      this.rank[rootX]++;
    }

    this.componentsCount--;
    return true;
  }

  connected(x, y) {
    return this.find(x) === this.find(y);
  }
}

function merge(intervals) {
  if (intervals.length <= 1) return intervals;

  // Step 1: Sort by start time
  intervals.sort((a, b) => a[0] - b[0]);

  const merged = [intervals[0]];

  for (let i = 1; i < intervals.length; i++) {
    const prev = merged[merged.length - 1];
    const curr = intervals[i];

    // Overlapping condition: curr.start <= prev.end
    if (curr[0] <= prev[1]) {
      prev[1] = Math.max(prev[1], curr[1]);
    } else {
      merged.push(curr);
    }
  }

  return merged;
}

function eraseOverlapIntervals(intervals) {

function jump(nums) {
  let jumps = 0;
  let curEnd = 0;
  let curFarthest = 0;

  for (let i = 0; i < nums.length - 1; i++) {
    curFarthest = Math.max(curFarthest, i + nums[i]);

    if (i === curEnd) {
      jumps++;
      curEnd = curFarthest;
      if (curEnd >= nums.length - 1) break;
    }
  }

  return jumps;
}

function canCompleteCircuit(gas, cost) {
  let totalSurplus = 0;
  let currentFuel = 0;
  let startStation = 0;

  for (let i = 0; i < gas.length; i++) {
    const net = gas[i] - cost[i];
    totalSurplus += net;
    currentFuel += net;

    if (currentFuel < 0) {
      // Cannot start anywhere from startStation to i, reset start to i + 1
      startStation = i + 1;
      currentFuel = 0;
    }
  }

  return totalSurplus >= 0 ? startStation : -1;
}

function candy(ratings) {
  const n = ratings.length;
  const candies = new Array(n).fill(1);

  // Pass 1: Left to Right
  for (let i = 1; i < n; i++) {
    if (ratings[i] > ratings[i - 1]) {
      candies[i] = candies[i - 1] + 1;
    }
  }

  // Pass 2: Right to Left
  for (let i = n - 2; i >= 0; i--) {
    if (ratings[i] > ratings[i + 1]) {
      candies[i] = Math.max(candies[i], candies[i + 1] + 1);
    }
  }

  return candies.reduce((sum, c) => sum + c, 0);
}

function minPathSum(grid) {

  const n = grid[0].length;

  for (let r = 0; r < m; r++) {
    for (let c = 0; c < n; c++) {

function canPartition(nums) {
  const totalSum = nums.reduce((a, b) => a + b, 0);
  if (totalSum % 2 !== 0) return false; // Odd sum cannot be partitioned equally

  const target = totalSum / 2;
  const dp = new Array(target + 1).fill(false);

    // Traverse backwards to prevent using the same element twice (0/1 rule)!

  }

}

function longestCommonSubsequence(text1, text2) {
  const m = text1.length;
  const n = text2.length;
  const dp = Array.from({ length: m + 1 }, () => new Array(n + 1).fill(0));

  for (let i = m - 1; i >= 0; i--) {
    for (let j = n - 1; j >= 0; j--) {
      if (text1[i] === text2[j]) {
        dp[i][j] = 1 + dp[i + 1][j + 1];
      } else {
        dp[i][j] = Math.max(dp[i + 1][j], dp[i][j + 1]);
      }
    }
  }

  return dp[0][0];
}

function minDistance(word1, word2) {
  const m = word1.length;
  const n = word2.length;
  const dp = Array.from({ length: m + 1 }, () => new Array(n + 1).fill(0));

  // Base cases: transforming empty string
  for (let i = 0; i <= m; i++) dp[i][0] = i;
  for (let j = 0; j <= n; j++) dp[0][j] = j;

  for (let i = 1; i <= m; i++) {
    for (let j = 1; j <= n; j++) {
      if (word1[i - 1] === word2[j - 1]) {
        dp[i][j] = dp[i - 1][j - 1]; // No op needed
      } else {
        dp[i][j] = 1 + Math.min(
          dp[i - 1][j],     // Delete
          dp[i][j - 1],     // Insert
          dp[i - 1][j - 1]  // Replace
        );
      }
    }
  }

  return dp[m][n];
}

function lengthOfLIS(nums) {
  const tails = []; // tails[i] stores smallest tail of all increasing subseq of length i+1

  for (const x of nums) {
    let low = 0, high = tails.length - 1;
    let idx = tails.length;

    while (low <= high) {
      const mid = low + Math.floor((high - low) / 2);
      if (tails[mid] >= x) {
        idx = mid;
        high = mid - 1;
      } else {
        low = mid + 1;
      }
    }

    if (idx === tails.length) {
      tails.push(x);
    } else {
      tails[idx] = x;
    }
  }

  return tails.length;
}

function robTree(root) {
  function dfs(node) {
    if (!node) return [0, 0]; // [rob, skip]

    const [leftRob, leftSkip] = dfs(node.left);
    const [rightRob, rightSkip] = dfs(node.right);

    // If we rob this node, we CANNOT rob its immediate children
    const rob = node.val + leftSkip + rightSkip;

    // If we skip this node, we take max from children
    const skip = Math.max(leftRob, leftSkip) + Math.max(rightRob, rightSkip);

    return [rob, skip];
  }

  const [rob, skip] = dfs(root);
  return Math.max(rob, skip);
}

#3. Single Number III (LeetCode #260)

Array mein exactly 2 distinct numbers ek baar aate hain ($A$ aur $B$), baaki sab do baar. Find both $A$ and $B$.

Algorithmic Strategy:

  1. Pure array ka cumulative XOR nikaalo: $X = A \oplus B$. Chunki $A \neq B$, toh $X \neq 0$ hoga, yaani kam se kam ek bit par $A$ aur $B$ differ karte hain!
  2. $X$ ki sabse lowest set bit dhoondo: diff = X & (-X). Yeh bit ya toh $A$ mein 1 hogi ya $B$ mein, lekin dono mein 1 nahi ho sakti!
  3. Pure array ko 2 groups mein partition kar do based on whether (num & diff) !== 0:

function singleNumberIII(nums) {
  // Step 1: XOR of all elements = A ^ B
  let xor = 0;
  for (const num of nums) {
    xor ^= num;
  }

  // Step 2: Find rightmost set bit
  const diffBit = xor & (-xor);

  // Step 3: Divide into two buckets and XOR
  let a = 0;
  let b = 0;

  for (const num of nums) {
    if ((num & diffBit) !== 0) {
      a ^= num; // Bucket 1
    } else {
      b ^= num; // Bucket 2
    }
  }

  return [a, b];
}

  • Kisi bhi number $i$ ko 1 bit right shift karne par (i >> 1), uski last bit hat jaati hai aur baaki bits wahi rehti hain!
  • Iska matlab: $i$ ke 1-bits ki sankhya = $(i >> 1)$ ke 1-bits + last bit ($i \& 1$).
  • DP Formula: dp[i] = dp[i >> 1] + (i & 1)
⚡ JAVASCRIPT 
function countBits(n) {
  const dp = new Array(n + 1).fill(0);

  for (let i = 1; i <= n; i++) {
    // i >> 1 has already been calculated!
    // i & 1 checks if the current number is odd (last bit is 1)
    dp[i] = dp[i >> 1] + (i & 1);
  }

  return dp;
}

#3. Reverse Bits (LeetCode #190)

Ek 32-bit unsigned integer ke saare bits ko reverse karo.

Approach: 32 iterations ka loop chalao. Har step par result ko 1 position left shift karo aur n ki last bit (n & 1) ko result ke rightmost slot mein add karo. Phir n ko unsigned right shift (n >>> 1) karo.

⚡ JAVASCRIPT 
function reverseBits(n) {
  let result = 0;

  for (let i = 0; i < 32; i++) {
    // Left shift result to make room, then insert lowest bit of n
    result = (result << 1) | (n & 1);
    // Unsigned right shift to bring next bit to position 0
    n = n >>> 1;
  }

  // Convert to unsigned 32-bit integer
  return result >>> 0;
}

#3. Divide Two Integers without `*`, `/`, `%` (LeetCode #29)

Do 32-bit integers divide karo bina multiplication, division, ya modulo use kiye. $O(\log^2 N)$ time.

Core Concept (Exponential Bit Doubling):

Ek-ek karke subtract karne mein $O(N)$ lag jayega jo TLE dega. Lekin agar divisor ko left shift karte jayein (divisor << shift), toh woh double hota jayega: $1x, 2x, 4x, 8x, 16x \dots$
Sabse bada chunk subtract karo, answer mein $2^{shift}$ add karo, aur repeat karo!

⚡ JAVASCRIPT 
function divide(dividend, divisor) {
  // Edge Case: 32-bit signed integer overflow (-2^31 / -1 = 2^31 > MAX_INT)
  const MAX_INT = 2147483647;
  const MIN_INT = -2147483648;
  if (dividend === MIN_INT && divisor === -1) return MAX_INT;

  // Determine sign of quotient
  const isNegative = (dividend < 0) ^ (divisor < 0);

  // Work with positive values using Math.abs
  let dvd = Math.abs(dividend);
  const dvs = Math.abs(divisor);
  let quotient = 0;

  // Exponential subtraction
  while (dvd >= dvs) {
    let tempDivisor = dvs;
    let multiple = 1;

    // Double divisor as long as it fits inside dividend
    // Note: tempDivisor <= (dvd >>> 1) prevents overflow in doubling
    while (tempDivisor <= (dvd >>> 1)) {
      tempDivisor = tempDivisor << 1;
      multiple = multiple << 1;
    }

    dvd -= tempDivisor;
    quotient += multiple;
  }

  return isNegative ? -quotient : quotient;
}

#1. Subsets Generation via Bitmasking (LeetCode #78)

Array of size $N$ ke saare subsets (Power Set) generate karo. Total $2^N$ subsets hote hain.

Bitmask Insight:

  • $0$ se lekar $2^N - 1$ tak har integer binary mein $N$ bits ka hota hai.
  • Agar $j$-th bit 1 hai, iska matlab $j$-th element subset mein included hai.
  • Agar $j$-th bit 0 hai, iska matlab $j$-th element subset mein excluded hai.
  • Example: $N = 3$ ($[A, B, C]$):
    • 0 = 000 $\to []$
    • 1 = 001 $\to [A]$
    • 2 = 010 $\to [B]$
    • 3 = 011 $\to [A, B]$
    • 7 = 111 $\to [A, B, C]$
⚡ JAVASCRIPT 
function subsets(nums) {
  const n = nums.length;
  const totalSubsets = 1 << n; // 2^n
  const result = [];

  for (let mask = 0; mask < totalSubsets; mask++) {
    const currentSubset = [];
    for (let j = 0; j < n; j++) {
      // If j-th bit is set, include nums[j]
      if ((mask & (1 << j)) !== 0) {
        currentSubset.push(nums[j]);
      }
    }
    result.push(currentSubset);
  }

  return result;
}

#3. Maximum Product of Word Lengths (LeetCode #318)

⚡ JAVASCRIPT 
function maxProduct(words) {
  const n = words.length;
  const masks = new Array(n).fill(0);
  const lens = new Array(n).fill(0);

  for (let i = 0; i < n; i++) {
    let mask = 0;
    for (let c = 0; c < words[i].length; c++) {
      const bitIndex = words[i].charCodeAt(c) - 97; // 'a' is 97
      mask |= (1 << bitIndex);
    }
    masks[i] = mask;
    lens[i] = words[i].length;
  }

  let maxProd = 0;
  for (let i = 0; i < n; i++) {
    for (let j = i + 1; j < n; j++) {
      // If bitwise AND is 0, words share NO common letters!
      if ((masks[i] & masks[j]) === 0) {
        maxProd = Math.max(maxProd, lens[i] * lens[j]);
      }
    }
  }

  return maxProd;
}

TOPIC 66: Segment Trees (Point & Range Queries)

The definitive tree structure for dynamic range queries: Combining O(log N) point updates and O(log N) associative range aggregations (Sum, Min, Max, GCD).

🌲 Binary Tree in Array: 4N array representation representing interval segments
⚡ O(log N) Point Update: Propagates modified value up the tree to root
🎯 O(log N) Range Query: Decomposes any arbitrary range [L, R] into at most 2 * log N nodes

#1. Why Do We Need Segment Trees?

Dilemma samjhein: Agar array mein humein frequent Range Queries (e.g. sum, min, max between $[L, R]$) aur frequent Updates dono handle karni hon:

Data Structure Range Query Time Point Update Time Verdict
Raw Array $O(N)$ (Iterate from $L$ to $R$) $O(1)$ (Array index assign) Too slow for queries
Prefix Sum Array $O(1)$ (pref[R] - pref[L-1]) $O(N)$ (Must rebuild prefix array) Too slow for updates
Segment Tree $O(\log N)$ $O(\log N)$ Optimal for Dynamic Streams!

#2. Anatomy of a Segment Tree

  • Root node represents entire range $[0, N-1]$.
  • Left child represents $[0, \text{mid}]$, right child represents $[\text{mid} + 1, N-1]$.
  • Leaves represent single elements $[i, i]$.
  • Max nodes needed: $4N$ (kyunki binary tree height $\lceil \log_2 N \rceil + 1$ hoti hai).
  • 3 Query Overlap Cases:
    1. No Overlap: Node range $[start, end]$ completely disjoint from $[L, R]$ $\to$ return neutral value ($0$ for sum, $\infty$ for min).
    2. Total Overlap: Node range $[start, end]$ is entirely inside $[L, R]$ $\to$ return tree[node] directly!
    3. Partial Overlap: Recurse into both left and right children and merge answers.
⚡ JAVASCRIPT 
class SegmentTree {
  constructor(nums) {
    this.n = nums.length;
    this.nums = nums;
    // 4 * N is the safe upper bound for complete binary tree of size N
    this.tree = new Array(4 * this.n).fill(0);
    if (this.n > 0) {
      this.build(1, 0, this.n - 1);
    }
  }

  // Build tree recursively: node = current index in tree array
  build(node, start, end) {
    if (start === end) {
      this.tree[node] = this.nums[start];
      return;
    }
    const mid = Math.floor((start + end) / 2);
    const leftChild = 2 * node;
    const rightChild = 2 * node + 1;

    this.build(leftChild, start, mid);
    this.build(rightChild, mid + 1, end);

    // Merge step (Sum aggregation)
    this.tree[node] = this.tree[leftChild] + this.tree[rightChild];
  }

  // Point Update: index idx in original array to val
  update(idx, val) {
    this._update(1, 0, this.n - 1, idx, val);
  }

  _update(node, start, end, idx, val) {
    if (start === end) {
      this.nums[idx] = val;
      this.tree[node] = val;
      return;
    }
    const mid = Math.floor((start + end) / 2);
    const leftChild = 2 * node;
    const rightChild = 2 * node + 1;

    if (idx <= mid) {
      this._update(leftChild, start, mid, idx, val);
    } else {
      this._update(rightChild, mid + 1, end, idx, val);
    }

    this.tree[node] = this.tree[leftChild] + this.tree[rightChild];
  }

  // Range Query: sum from index l to r inclusive
  query(l, r) {
    return this._query(1, 0, this.n - 1, l, r);
  }

  _query(node, start, end, l, r) {
    // Case 1: Node segment is completely outside [l, r]
    if (r < start || end < l) return 0;

    // Case 2: Node segment is completely inside [l, r]
    if (l <= start && end <= r) return this.tree[node];

    // Case 3: Partial overlap -> query both children
    const mid = Math.floor((start + end) / 2);
    const leftSum = this._query(2 * node, start, mid, l, r);
    const rightSum = this._query(2 * node + 1, mid + 1, end, l, r);

    return leftSum + rightSum;
  }
}

TOPIC 67: Segment Tree with Lazy Propagation

Upgrading range updates from O(N log N) to O(log N) through deferred evaluation: Postponing child updates until queries demand them.

⏳ Lazy Evaluation: Store pending updates in lazy[node] instead of traversing down
⚡ O(log N) Range Update: Updates an entire range [L, R] by +val in logarithmic time
📬 Push Down Mechanism: Transfers pending tags to children just-in-time during traversal

#1. The Range Update Bottleneck

Agar hum normal Segment Tree mein range update karein (jaise: add $+5$ to all elements from index $L$ to $R$), toh humein range ke har leaf node tak travel karna padega. $K$ elements ke liye time $O(K \log N) = O(N \log N)$ ho jayega, jo raw array se bhi slow hai!

Lazy Propagation Philosophy:
"Jab tak kaam ki sakht zaroorat na ho, tab tak mat karo!"
Agar koi node pura $[L, R]$ ke andar aa jata hai, toh uske children tak travel karne ke bajaye hum us node par ek lazy tag laga dete hain aur wahin se return ho jaate hain. Jab bhavishya mein koi query uske children ki demand karegi, sirf tabhi hum us tag ko neeche push karenge (Push-Down mechanism)!

⚡ JAVASCRIPT 
class LazySegmentTree {
  constructor(nums) {
    this.n = nums.length;
    this.nums = nums;
    this.tree = new Array(4 * this.n).fill(0);
    this.lazy = new Array(4 * this.n).fill(0);
    if (this.n > 0) this.build(1, 0, this.n - 1);
  }

  build(node, start, end) {
    if (start === end) {
      this.tree[node] = this.nums[start];
      return;
    }
    const mid = Math.floor((start + end) / 2);
    this.build(2 * node, start, mid);
    this.build(2 * node + 1, mid + 1, end);
    this.tree[node] = this.tree[2 * node] + this.tree[2 * node + 1];
  }

  // Push pending lazy update to children
  pushDown(node, start, end) {
    if (this.lazy[node] !== 0) {
      const val = this.lazy[node];
      const mid = Math.floor((start + end) / 2);

      // Apply to left child
      this.lazy[2 * node] += val;
      this.tree[2 * node] += val * (mid - start + 1);

      // Apply to right child
      this.lazy[2 * node + 1] += val;
      this.tree[2 * node + 1] += val * (end - mid);

      // Clear current node's lazy tag
      this.lazy[node] = 0;
    }
  }

  // Range Update: add val to all elements in range [l, r]
  updateRange(l, r, val) {
    this._updateRange(1, 0, this.n - 1, l, r, val);
  }

  _updateRange(node, start, end, l, r, val) {
    // 1. Outside range
    if (r < start || end < l) return;

    // 2. Fully inside range -> Mark lazy tag and update current tree node
    if (l <= start && end <= r) {
      this.tree[node] += val * (end - start + 1);
      this.lazy[node] += val;
      return;
    }

    // 3. Partial overlap -> Push down then recurse
    this.pushDown(node, start, end);
    const mid = Math.floor((start + end) / 2);

    this._updateRange(2 * node, start, mid, l, r, val);
    this._updateRange(2 * node + 1, mid + 1, end, l, r, val);

    this.tree[node] = this.tree[2 * node] + this.tree[2 * node + 1];
  }

  // Range Query: sum from l to r
  queryRange(l, r) {
    return this._queryRange(1, 0, this.n - 1, l, r);
  }

  _queryRange(node, start, end, l, r) {
    if (r < start || end < l) return 0;
    if (l <= start && end <= r) return this.tree[node];

    this.pushDown(node, start, end);
    const mid = Math.floor((start + end) / 2);

    return this._queryRange(2 * node, start, mid, l, r) +
           this._queryRange(2 * node + 1, mid + 1, end, l, r);
  }
}

TOPIC 68: Binary Indexed Tree (Fenwick Tree)

The ultra-compact, cache-friendly data structure that implements prefix sums and point updates in 10 lines of code with O(N) space and O(log N) runtime.

💡 Bit Index Magic: Node i is responsible for range [i - (i & -i) + 1, i]
⚡ O(log N) Prefix Sum: Travels down by clearing lowest set bit: i -= (i & -i)
🚀 O(log N) Point Update: Travels up by adding lowest set bit: i += (i & -i)

#1. Fenwick Tree vs Segment Tree

Feature Fenwick Tree (BIT) Segment Tree
Memory $N + 1$ elements ($O(N)$ minimal) $4N$ elements
Code Complexity 10 lines (Ultra clean) 50–80 lines
Constant Factor 2-3x faster (L1 cache friendly) Slightly slower pointer jumps
Supported Operations Invertible operations (Sum, XOR) Any associative operation (Min, Max, GCD)

#2. The Bit Math Behind Fenwick Trees

  • Fenwick tree 1-indexed use karta hai.
  • Har index $i$ apne binary representation ke rightmost set-bit ke barabar lambai ki interval store karta hai: $\text{len} = i \& (-i)$.
  • Index $12$ (binary $1100_2$): lowest set bit is $4$ ($0100_2$). Toh $12$ index range $[12 - 4 + 1, 12] = [9, 12]$ ka sum store karta hai!
  • Query(i): $i \to i - (i \& -i)$ karke jump lagate hain jab tak $0$ na aa jaye. Max $\log_2 N$ steps!
  • Update(i, delta): $i \to i + (i \& -i)$ karke parent nodes ko update karte hain. Max $\log_2 N$ steps!
⚡ JAVASCRIPT 
class FenwickTree {
  // 1-indexed implementation
  constructor(size) {
    this.n = size;
    this.tree = new Array(this.n + 1).fill(0);
  }

  // Point Update: Add delta to element at index i (1-indexed)
  update(i, delta) {
    while (i <= this.n) {
      this.tree[i] += delta;
      i += (i & -i); // Add lowest set bit (travels to parent)
    }
  }

  // Prefix Sum: Calculate sum from index 1 to i
  query(i) {
    let sum = 0;
    while (i > 0) {
      sum += this.tree[i];
      i -= (i & -i); // Strip lowest set bit (travels to next range)
    }
    return sum;
  }

  // Range Sum Query: Sum in range [l, r] (1-indexed)
  queryRange(l, r) {
    return this.query(r) - this.query(l - 1);
  }

  // Build BIT from existing array in O(N)
  static buildFromArray(arr) {
    const bit = new FenwickTree(arr.length);
    for (let i = 0; i < arr.length; i++) {
      bit.update(i + 1, arr[i]);
    }
    return bit;
  }
}

TOPIC 69: String Matching — KMP Algorithm (Knuth-Morris-Pratt)

Linear time O(N + M) substring matching: Eliminating redundant backtracking by precomputing the Longest Proper Prefix which is also a Suffix (LPS array).

⚡ Linear Time O(N + M): Never backtracks text pointer i, only shifts pattern pointer j
📐 LPS Array Construction: Precomputes length of longest prefix matching proper suffix in O(M)
🎯 Needle in Haystack (#28): The optimal algorithm for exact pattern matching on massive streams

#1. Why Naive String Matching Fails ($O(N \times M)$)

Agar text ho: "AAAAAAAAAAAAAAAAAB" aur pattern ho: "AAAAB":

  • Naive approach har mismatch par text pointer ko wapas peeche le jaata hai. Isse $O(N \times M)$ comparison lagte hain jo TLE deta hai.
  • KMP Insight: Jab match ke baad mismatch hota hai, hum already jaan chuke hain ki text ke pichle characters kya the! Unhe dubara check karne ki zaroorat nahi hai. Hum pattern pointer $j$ ko LPS value par jump karwa dete hain while text pointer $i$ sirf aage badhta rehta hai!
⚡ JAVASCRIPT 
class KMP {
  // Step 1: Compute LPS Array (Longest Proper Prefix which is also Suffix)
  static buildLPS(pattern) {
    const m = pattern.length;
    const lps = new Array(m).fill(0);
    let len = 0; // length of previous longest prefix suffix
    let i = 1;

    while (i < m) {
      if (pattern[i] === pattern[len]) {
        len++;
        lps[i] = len;
        i++;
      } else {
        if (len !== 0) {
          // Fall back to previous prefix boundary
          len = lps[len - 1];
        } else {
          lps[i] = 0;
          i++;
        }
      }
    }

    return lps;
  }

  // Step 2: Search pattern in text (LeetCode #28)
  static search(text, pattern) {
    const n = text.length;
    const m = pattern.length;
    if (m === 0) return 0;

    const lps = KMP.buildLPS(pattern);
    const occurrences = [];
    let i = 0; // index for text
    let j = 0; // index for pattern

    while (i < n) {
      if (text[i] === pattern[j]) {
        i++;
        j++;
      }

      if (j === m) {
        // Match found at index (i - j)
        occurrences.push(i - j);
        j = lps[j - 1]; // prepare for next potential match
      } else if (i < n && text[i] !== pattern[j]) {
        // Mismatch after j matches
        if (j !== 0) {
          // Key KMP Step: Do not decrement i, jump j using LPS
          j = lps[j - 1];
        } else {
          i++;
        }
      }
    }

    return occurrences;
  }
}

TOPIC 70: String Matching — Rabin-Karp Rolling Hash

Polynomial rolling hashes for O(1) sliding window substring fingerprinting: Solving Repeated DNA Sequences (#187) and Longest Duplicate Substring (#1044).

🔑 Rolling Hash Formula: Hash = (Hash - leadingChar * Base^(M-1)) * Base + trailingChar
⚡ O(1) Window Slide: Computes hash of next substring in constant time
🛡️ Collision Resolution: Double hash or exact string verification to prevent hash collisions

#1. The Rolling Hash Mechanism

String ko ek polynomial base number system ki tarah treat karein:

$$\text{Hash}(S) = \left(S[0] \cdot B^{M-1} + S[1] \cdot B^{M-2} + \dots + S[M-1] \cdot B^0\right) \pmod{MOD}$$

Jab window 1 step right shift hoti hai:

  1. Pehle character ka contribution subtract karo: (Hash - S[0] * B^(M-1))
  2. Bache hue ko $B$ se multiply karo (har character ek position left shift ho jata hai).
  3. Naye character ko add karo: + S[M].

Yeh pure calculation ko $O(1)$ constant time mein kar deta hai!

⚡ JAVASCRIPT 
function findRepeatedDnaSequences(s) {
  // LeetCode #187: Find all 10-letter substrings that occur more than once
  const L = 10;
  const n = s.length;
  if (n <= L) return [];

  // Map 4 bases to 2-bit integers: A=0, C=1, G=2, T=3
  const toVal = { 'A': 0, 'C': 1, 'G': 2, 'T': 3 };
  const BASE = 4;
  const MOD = 1000000007;

  // Compute base^(L-1) mod MOD
  let baseL = 1;
  for (let i = 0; i < L - 1; i++) {
    baseL = (baseL * BASE) % MOD;
  }

  // Calculate initial hash of first window
  let h = 0;
  for (let i = 0; i < L; i++) {
    h = (h * BASE + toVal[s[i]]) % MOD;
  }

  const seen = new Set([h]);
  const repeated = new Set();

  for (let i = 1; i <= n - L; i++) {
    // 1. Remove outgoing char s[i - 1]
    const outVal = toVal[s[i - 1]];
    h = (h - (outVal * baseL) % MOD + MOD) % MOD;

    // 2. Shift left and add incoming char s[i + L - 1]
    const inVal = toVal[s[i + L - 1]];
    h = (h * BASE + inVal) % MOD;

    if (seen.has(h)) {
      repeated.add(s.substring(i, i + L));
    } else {
      seen.add(h);
    }
  }

  return Array.from(repeated);
}

TOPIC 71: String Matching — Z-Algorithm

Linear time Z-array computation: Finding the Longest Common Prefix of every suffix with the prefix using the dynamic Z-box [L, R] interval.

📏 Z-Array Definition: Z[i] is length of longest substring starting at i matching prefix of S
📦 The Z-Box [L, R]: Maintains rightmost interval that matches prefix to skip redundant comparisons
⚡ O(N) Total Runtime: Every character is compared at most twice as R moves strictly rightward

#1. How the Z-Algorithm Works

Z-Algorithm ek string $S$ ke liye ek array $Z$ banata hai jahan $Z[i]$ yeh batata hai ki index $i$ se start hone wala substring, string ke prefix $S[0 \dots]$ se kitne characters match karta hai.

Pattern Matching Trick:

  1. Ek nayi string banao: concat = Pattern + '#' + Text (jahan '#' koi special character hai jo text ya pattern mein nahi hai).
  2. Is concat string par Z-array calculate karo.
  3. Agar kisi index $i > \text{pattern.length}$ par $Z[i] === \text{pattern.length}$ ho, toh iska matlab pattern text mein match ho gaya hai!
⚡ JAVASCRIPT 
function computeZArray(s) {
  const n = s.length;
  const z = new Array(n).fill(0);
  let l = 0;
  let r = 0;

  for (let i = 1; i < n; i++) {
    if (i <= r) {
      // i falls inside the current Z-box [l, r]
      // Use previously computed value at symmetric position (i - l)
      z[i] = Math.min(r - i + 1, z[i - l]);
    }

    // Try to extend the match beyond r
    while (i + z[i] < n && s[z[i]] === s[i + z[i]]) {
      z[i]++;
    }

    // If new interval extends beyond current r, update Z-box [l, r]
    if (i + z[i] - 1 > r) {
      l = i;
      r = i + z[i] - 1;
    }
  }

  return z;
}

// Pattern matching using Z-algorithm
function zSearch(text, pattern) {
  // Delimiter '#' must not appear in text or pattern
  const concat = pattern + '#' + text;
  const z = computeZArray(concat);
  const m = pattern.length;
  const matches = [];

  for (let i = m + 1; i < concat.length; i++) {
    if (z[i] === m) {
      // Match found in text at index: i - (m + 1)
      matches.push(i - (m + 1));
    }
  }

  return matches;
}

TOPIC 72: Advanced Graphs — Strongly Connected Components (Tarjan & Kosaraju)

Decomposing directed graphs into maximal strongly connected subgraphs where every vertex is mutually reachable, and identifying critical network bridges.

🔁 Kosaraju's 2-Pass DFS: DFS on G to record finishing times + DFS on transposed graph G^T
⚡ Tarjan's Single-Pass DFS: Uses discovery time (disc) and low-link values (low) on stack
🌉 Critical Connections (#1192): Finds network bridges where low[v] > disc[u]

#1. What is a Strongly Connected Component (SCC)?

Directed graph mein ek subset of vertices ko Strongly Connected Component kehte hain agar us component ke har pair $(u, v)$ ke beech path exist karta ho ($u \to v$ AND $v \to u$).

  • Kosaraju's Algorithm:
    1. Graph $G$ par DFS chalao aur finishing order ke hisaab se nodes ko stack mein push karo.
    2. Graph ki saari edges reverse karke transposed graph $G^T$ banao.
    3. Stack se ek-ek node nikaal kar $G^T$ par DFS chalao. Har DFS traversal ek independent SCC nikalegi!
  • Tarjan's Bridge Algorithm:

    Undirected graph mein agar kisi edge $(u, v)$ ko hatane se graph do disconnect components mein divide ho jaye, toh use Bridge (Critical Connection) kehte hain. Condition: low[v] > disc[u].

⚡ JAVASCRIPT 
// LeetCode #1192: Critical Connections in a Network (Tarjan's Bridge Finding)
function criticalConnections(n, connections) {
  // Step 1: Build undirected adjacency list
  const adj = Array.from({ length: n }, () => []);
  for (const [u, v] of connections) {
    adj[u].push(v);
    adj[v].push(u);
  }

  const disc = new Array(n).fill(-1); // discovery time of each node
  const low = new Array(n).fill(-1);  // lowest discovery time reachable
  const bridges = [];
  let timer = 0;

  function dfs(u, parent) {
    disc[u] = low[u] = timer++;

    for (const v of adj[u]) {
      if (v === parent) continue; // do not go back to immediate parent

      if (disc[v] !== -1) {
        // Back-edge found: update low of current node
        low[u] = Math.min(low[u], disc[v]);
      } else {
        // Forward edge: recurse DFS
        dfs(v, u);
        low[u] = Math.min(low[u], low[v]);

        // Bridge Condition: If lowest reachable node from v is strictly
        // greater than discovery time of u, then edge (u, v) is a BRIDGE!
        if (low[v] > disc[u]) {
          bridges.push([u, v]);
        }
      }
    }
  }

  for (let i = 0; i < n; i++) {
    if (disc[i] === -1) {
      dfs(i, -1);
    }
  }

  return bridges;
}

TOPIC 73: Advanced Graphs — Eulerian Path & Circuit (Hierholzer's Algorithm)

Traversing every single edge in a graph exactly once: Degree existence conditions and Hierholzer's post-order DFS algorithm for Reconstruct Itinerary (#332).

🛤️ Eulerian Path vs Circuit: Euler Path visits all edges once; Circuit starts and ends at same node
📊 In-Degree / Out-Degree: Condition: outDegree[u] - inDegree[u] === 1 for start node
✈️ Reconstruct Itinerary (#332): Greedy lexical sorting + Hierholzer's post-order reversal

#1. Eulerian Path Existence Theorems

Directed Graph Rule:

  1. Eulerian Circuit: Graph ke har vertex ka inDegree[v] === outDegree[v] hona chahiye.
  2. Eulerian Path: Exactly ek vertex ka outDegree - inDegree === 1 (Start node) hona chahiye, exactly ek vertex ka inDegree - outDegree === 1 (End node) hona chahiye, aur baaki sabka inDegree === outDegree hona chahiye!

Hierholzer's Algorithm:
Start node se DFS start karo. Har visited edge ko graph se turant remove karo. Jab koi node aage nahi jaa sakta (dead-end), toh usko result list mein add karo. Akhir mein list ko reverse karne par perfect Eulerian Path mil jaata hai!

⚡ JAVASCRIPT 
// LeetCode #332: Reconstruct Itinerary (Hierholzer's Algorithm)
function findItinerary(tickets) {
  // Step 1: Build graph with lexically sorted destination lists
  const adj = new Map();
  for (const [from, to] of tickets) {
    if (!adj.has(from)) adj.set(from, []);
    adj.get(from).push(to);
  }

  // Sort destinations in reverse lexical order so we can use fast pop()
  for (const [from, dests] of adj.entries()) {
    dests.sort().reverse();
  }

  const itinerary = [];

  // Step 2: Post-order DFS (Hierholzer's traversal)
  function dfs(airport) {
    const dests = adj.get(airport);
    while (dests && dests.length > 0) {
      const nextAirport = dests.pop(); // Visit edge and delete it
      dfs(nextAirport);
    }
    // All outgoing edges from this node have been traversed!
    itinerary.push(airport);
  }

  dfs("JFK");

  // Reverse post-order to get Eulerian path
  return itinerary.reverse();
}

TOPIC 74: Advanced Dynamic Programming Optimizations

Cutting polynomial complexity down: Divide & Conquer optimization, Knuth's Monotonicity optimization, and Convex Hull Trick (CHT) mental models.

✂️ Divide & Conquer Optimization: Reduces O(K * N^2) to O(K * N log N) using optimal split monotonicity
📐 Knuth's Optimization: Reduces O(N^3) interval DP to O(N^2) via opt[i][j-1] <= opt[i][j] <= opt[i+1][j]
📈 Convex Hull Trick (CHT): Evaluates dynamic minimum of linear functions y = m*x + c in O(log N)

#1. When Do Advanced DP Optimizations Apply?

  • Divide & Conquer DP: Jab recurrence dp[i][j] = min_{k < j} (dp[i-1][k] + C[k][j]) ho, aur cost function Quadrangle Inequality satisfy karta ho: $$C[a][c] + C[b][d] \le C[a][d] + C[b][c] \quad \text{for } a \le b \le c \le d$$ Isse optimal split index $opt[i][j]$ monotonic ho jata hai, jisse time $O(K \cdot N^2)$ se gir kar $O(K \cdot N \log N)$ ho jata hai!
  • Convex Hull Trick (CHT): Jab DP transition linear functions $y = m \cdot x + c$ ke form mein ho, toh convex hull maintain karke $O(N)$ linear time mein global minimum/maximum query kiya ja sakta hai.
⚡ JAVASCRIPT 
// Knuth's Optimization Pattern Outline
// For Recurrence: dp[i][j] = min_{i <= k < j} (dp[i][k] + dp[k+1][j]) + cost(i, j)
// Normal evaluation: O(N^3)
// With Knuth's condition (Quadrangle inequality):
// opt[i][j-1] <= opt[i][j] <= opt[i+1][j]
// Runtime reduces from O(N^3) to O(N^2)!

function knuthOptimization(nums) {
  const n = nums.length;
  const dp = Array.from({ length: n }, () => new Array(n).fill(Infinity));
  const opt = Array.from({ length: n }, () => new Array(n).fill(0));

  // Base cases of length 1
  for (let i = 0; i < n; i++) {
    dp[i][i] = 0;
    opt[i][i] = i;
  }

  // Iterate over segment length
  for (let len = 2; len <= n; len++) {
    for (let i = 0; i <= n - len; i++) {
      const j = i + len - 1;
      const kStart = opt[i][j - 1];
      const kEnd = opt[i + 1][j];

      for (let k = kStart; k <= Math.min(j - 1, kEnd); k++) {
        const val = dp[i][k] + dp[k + 1][j] + (/* cost(i, j) */ 0);
        if (val < dp[i][j]) {
          dp[i][j] = val;
          opt[i][j] = k;
        }
      }
    }
  }

  return dp[0][n - 1];
}
